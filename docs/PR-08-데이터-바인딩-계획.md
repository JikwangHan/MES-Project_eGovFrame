# PR-08: 데이터 바인딩 계획(초안)

## 범위
- 대시보드
- 설비현황
- 수주
- 작업
- KPI

## 화면-API 매핑(초안)
| 화면 | 우선 API | 비고 |
| --- | --- | --- |
| 대시보드 | GET /api/dashboard/summary | 요약 지표 |
| 설비현황(목록) | GET /api/equipments | 상태/마지막 수신 |
| 설비현황(상세) | GET /api/equipments/{deviceId}/telemetry | 장비별 이력 |
| 수주 | GET /api/orders | 샘플 데이터(로컬) |
| 작업 | GET /api/jobs | 샘플 데이터(로컬) |
| KPI | GET /api/kpi | 샘플 데이터(로컬) |
| KPI 추이 | GET /api/kpi/trend | 샘플 데이터(로컬) |

## 바인딩 원칙
- 계약 API 우선, 미정 구간은 샘플로 대체한다.
- 화면 데이터가 비어도 예외 없이 렌더한다.
- 변경 가능하며, 확정 전까지 수정 가능하다.

## 바인딩 처리 방식(초안)
- UI 페이지에서 `/api/*` 호출 후 테이블에 바인딩한다.
- 실패 시 빈 상태를 유지하고 에러 화면은 만들지 않는다.
- 차트/그리드는 오픈소스 선정 후 단계적으로 교체한다.

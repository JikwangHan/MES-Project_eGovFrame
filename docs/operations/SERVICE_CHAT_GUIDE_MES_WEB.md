# 서비스별 Chat 통합 가이드 (MES Web)

본 문서는 MES Web 서비스 전용 Chat에서 필요한 환경설정, 작업 범위, 커밋/업로드 규칙, 충돌 방지, 공통 변경 요청까지 한 번에 확인할 수 있는 통합 가이드입니다.

## 0) 역할 요약
- 목적: MES Web 범위만 개발하고, 다른 서비스와 충돌 없이 안전하게 협업
- 원칙: 범위 밖 파일은 수정하지 않음, 공통 변경은 공통 기준 Chat에 요청

## 1) 작업 범위(허용/금지 경로)
### 1-1) 허용 경로(수정 가능)
- `mes-web-egov/`
  - `mes-web-egov/src/`
  - `mes-web-egov/src/main/`
  - `mes-web-egov/src/main/java/`
  - `mes-web-egov/src/main/resources/`
  - `mes-web-egov/src/main/webapp/`

### 1-2) 금지 경로(수정 금지)
- `mes-common/`
- `mes-contracts/`
- `ai-middleware-egov/`
- `edge-gateway-egov/`
- `docs/User_Request/` (로컬 전용)
- `E:\VSCode_Codex\MES-Project_eGovFrame\` (일별 진행 파일)
- `mes-web-egov/target/` (빌드 산출물)
- `mes-web-egov/tomcat.18080/` (로컬 실행 산출물)

### 1-3) 공통 파일(변경 금지) 예시
- 루트 `pom.xml`
- `mes-common/` 아래 공통 유틸
- `mes-contracts/` 아래 계약/스키마
- `docs/operations/` 공통 운영 문서

## 2) 환경설정(최소 기준)
- JDK 17, Tomcat 9 기준
- Maven 빌드 기준
- 네트워크/저장소는 공통 기준 문서 준수
- 개인 PC 환경에서 실행 시: 로컬 설정만 사용, 민감정보는 문서/로그에 남기지 않음

## 3) 브랜치 규칙
- 기준 브랜치 최신화 후 분기
- 브랜치명: `service/mes-web/<작업키워드>`
  - 예: `service/mes-web/ui-p0`

## 4) 작업 절차(초보자용)
1. 작업 범위를 확인한다.
2. 수정 대상 파일이 허용 경로인지 확인한다.
3. 범위 밖 파일이 섞였으면 작업을 중단한다.
4. 변경 작업을 진행한다.
5. 저장 후 변경 파일 목록을 확인한다.
6. 불필요 파일은 제외한다.
7. 커밋 메시지를 한국어로 상세히 작성한다.
8. 원격 브랜치로 업로드한다.

## 5) 커밋/업로드 규칙
- 한 번의 커밋: "기능 1개 + 스모크/테스트 + 문서" 기준
- 커밋 메시지/PR 제목/설명은 한국어로 상세히 작성
- docs/User_Request 및 일별 진행 파일은 GitHub에 올리지 않음

### 5-1) 커밋 메시지 예시
- `MES Web 대시보드 UI 스캐폴딩 보강`
- `MES Web 검색/필터 검증 로직 추가`
- `MES Web 스모크 스크립트 갱신`

## 6) 충돌 방지 체크리스트
- 작업 전 기준 브랜치 최신화
- 공통 파일 변경 여부 확인(있으면 작업 중단)
- PR 전 `git status`로 불필요 파일 제외 확인
- 충돌 발생 시 공통 기준 Chat에 즉시 공유

## 7) 공통 변경 요청 형식(필수)
- 변경 대상 파일
- 변경 이유
- 변경 범위(추가/수정/삭제)

## 8) 로그/증빙 규칙
- 로그는 [PASS]/[FAIL]/[SKIP] 라인만 핵심 근거로 출력
- 민감정보(계정, 토큰, 내부 경로, 서버명)는 로그/문서에 남기지 않음

## 9) 주석 규칙
- 모든 코드 주석은 한국어
- 초보자가 이해할 수 있도록 기능/이유/흐름을 설명
- 핵심 로직은 왜 그렇게 구현했는지 이유를 반드시 작성

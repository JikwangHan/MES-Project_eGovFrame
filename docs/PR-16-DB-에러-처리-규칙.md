# PR-16: DB 연동 에러 처리 규칙(초안)

## 목적
- DB 연동 과정에서 발생하는 오류를 일관된 방식으로 처리한다.
- 민감정보(계정, 비밀번호, 내부 경로 등)는 응답/로그에 남기지 않는다.

## 범위
- MES Web 서비스의 DB 연동 구간(ApiController)

## 기본 원칙
1) 환경 변수(`MES_DB_URL`, `MES_DB_USER`, `MES_DB_PASSWORD`)가 모두 있을 때만 DB를 사용한다.
2) 환경 변수가 없으면 DB 미사용 모드로 자동 전환한다(메모리/샘플 데이터 사용).
3) DB 오류 발생 시 내부 예외는 외부로 노출하지 않는다.
4) 응답은 공통 포맷(`result`, `message`, `data`, `errorCode`)을 유지한다.

## 오류 유형별 처리(현 단계 기준)
- DB 미사용(환경 변수 누락):
  - 동작: 메모리/샘플 데이터로 처리
  - 응답: 정상 200/201 유지
  - 로그: `[SKIP]` 기준으로 스모크에서만 표시

- DB 연결 실패/쿼리 실패:
  - 동작: 예외 발생 시 5xx로 반환될 수 있음(현재 프레임워크 기본 동작)
  - 응답: 기본 500
  - 메시지: 내부 예외 메시지는 외부에 직접 노출하지 않음

## 향후 개선 방향(고도화 시)
- DB 오류를 공통 에러코드로 매핑:
  - 예: `DB-0001`(연결 실패), `DB-0002`(쿼리 실패)
- DB 오류 발생 시 `result: FAIL` + 사용자 안내 메시지 제공
- 장애 상황에서는 회복 가능한 범위만 메모리 폴백 적용 여부 검토
